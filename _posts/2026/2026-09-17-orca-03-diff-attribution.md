_영상 데모 — `Attribution.tsx` diff에 AI 요약과 검증 완료 표시가 함께 붙어 있다._

### Diff 뷰어 — "AI 코드를 진지하게 검토하기 위한" 설계

문서가 명시적으로 쓰는 표현이 "designed to review AI-generated code seriously"입니다. 기능 목록만 보면 여느 IDE의 diff 뷰어와 비슷해 보이지만, 세부적으로는 AI 코드 검토에 최적화된 항목들이 눈에 띕니다.

- **통합 diff 뷰**: 스테이징·언스테이징·미추적 파일을 한 화면에서
- **이미지 diff**: 바이너리 이미지를 나란히 비교, 스와이프, 어니언 스킨 모드
- **HTML 미리보기**: 작업 트리의 HTML을 브라우저 분할 창에서 바로 렌더링
- **병합 충돌 UI**: 3-way 뷰 + 인라인 해결
- **선택적 스테이징**: `git add -p`처럼 덩어리(hunk) 또는 라인 단위로 스테이징
- **공백 표시**: 스페이스/탭 등 숨겨진 문자를 검토 중에 시각화
- **파일 트리**: 통합 diff에서 접었다 펼 수 있는 파일 트리

키보드로만 리뷰를 끝낼 수 있도록 단축키도 촘촘합니다.

| 단축키 | 기능 |
|--------|------|
| `j` / `k` | 다음/이전 변경 파일 |
| `n` / `p` | 다음/이전 덩어리(hunk) |
| `s` | 현재 덩어리 스테이징 |
| `c` | 주석(코멘트) 시작 |

### Attribution — "이 줄, 사람이 썼어 AI가 썼어?"

diff 뷰어가 "무엇이 바뀌었나"를 보여준다면, **Attribution**은 "누가/무엇이 이 줄을 바꿨나"를 보여줍니다. 작동 방식은 이렇습니다.

> 에이전트가 파일에 쓸 때 Orca는 그 범위를 기록하고, diff 뷰어는 AI가 작성한 줄을 거터(gutter)에 미묘한 마커로 표시한다. 사람이 AI 코드 위에 다시 수정을 가하면, 그 부분은 다시 '인간 작성'으로 표시된다.

즉 라인 단위로 **AI 작성 / 인간 작성**이 동적으로 갱신되는 셈입니다. 스크린샷에서 보이는 "Fixed 1 defect", "Cogitated for 5m 19s" 같은 요약도 이 Attribution 파이프라인이 diff 옆에 붙여주는 정보로, 사람이 diff를 한 줄씩 읽기 전에 "이 커밋에서 에이전트가 실제로 뭘 고쳤는지"를 먼저 훑을 수 있게 해줍니다.

용도는 명확합니다.

- **리뷰 집중도**: AI가 대량으로 고친 보일러플레이트와, 사람이 손댄 핵심 로직을 구분해서 검토 강도를 다르게 줄 수 있음
- **보안/컴플라이언스 감사**: "AI가 작성한 코드"와 "인간이 작성한 코드"를 분리해서 추가 검토 대상을 고를 수 있음

한 가지 주의할 점 — Attribution 정보는 **Orca 내부에서만 유지되고 git 커밋에는 포함되지 않습니다.** 지속적으로 추적하고 싶다면 diff 도구 모음에서 메타데이터를 따로 내보내야 합니다.

### 정리

Orca의 리뷰 파이프라인은 "diff를 잘 보여주는 것"과 "diff에 컨텍스트를 얹어주는 것" 두 층으로 나뉩니다. 전자가 Diff 뷰어, 후자가 Attribution입니다. 에이전트가 많아질수록 diff 양도 늘어나는데, 이 둘이 합쳐지면 "일단 AI가 어디를 고쳤는지부터 보고, 필요한 곳만 라인 단위로 파고드는" 리뷰 루틴이 가능해집니다.
