[지난 글](/ai/ego-browser-review/)에서 유튜브 리뷰 영상을 통해 ego-browser(ego lite)의 개념과 데모를 살펴봤습니다. 이번 글은 [공식 문서(lite.ego.app)](https://lite.ego.app/document/ko/docs/quick-start)를 기준으로 설치, 아키텍처, 지원 에이전트, 실전 활용 시나리오를 더 깊이 정리합니다.

### 한 줄 정의

> ego (lite)는 **사용자와 AI 에이전트가 함께 쓰도록 설계된 브라우저**다. Chromium 엔진을 그대로 사용하며, 기존 Chrome 사용 경험(로그인, 쿠키, 확장 프로그램, 프로필)을 유지하면서 AI 에이전트 자동화 레이어를 얹은 형태다.

크롬 확장 프로그램이 아니라 **독립 실행형 프로그램**이라는 점이 중요합니다. 그래서 에이전트가 자동화를 걸어도 사용자가 평소 쓰던 Chrome 자체는 전혀 건드리지 않습니다.

### 설치와 초기 설정

- Mac용 DMG 파일로 배포
- 최초 실행 시 컴퓨터에 설치된 AI 에이전트(클로드 코드, 코덱스 등)를 자동으로 감지
- 기존 브라우저(Chrome 등)의 로그인 세션, 쿠키, 확장 프로그램, 프로필을 마이그레이션 가능
- 설치와 동시에 `ego-browser` 스킬이 `~/.agents/skills`, `~/.claude/skills/` 경로에 자동 생성됨 — 에이전트 쪽에서 별도 설정 없이 바로 `/ego-browser`로 호출 가능

### Space 아키텍처

문서에서 설명하는 Space는 에이전트가 **자체 격리된 작업 공간** 안에서 동작하도록 하는 핵심 메커니즘입니다.

- 에이전트가 작업을 시작해도 무작위로 새 창이 뜨거나 사용자의 기존 탭을 침범하지 않고, 백그라운드에서 조용히 실행
- 별도의 **Space 관리 패널**에서 현재 실행 중인 모든 에이전트 작업을 한눈에 모니터링
- 필요할 때 특정 Space에 개입(테이크오버)해서 사람이 직접 조작하고, 다시 에이전트에게 돌려줄 수 있음
- 이 구조 덕분에 병렬로 여러 에이전트를 돌려도 서로의 브라우저 컨트롤권을 두고 경쟁하지 않음

### 에이전트 연결 방식

1. 에이전트 채팅창에 `/ego-browser` 입력해 스킬 활성화
2. 권한을 **전체 액세스(Full Access)**로 설정 — 에이전트가 로컬에 설치된 ego(lite)를 직접 실행/제어할 수 있게 허용
3. 에이전트별로 권한 부여 방식이 다름 (예: Bypass permissions, 자동 승인 모드 등) — 사용 중인 에이전트의 권한 모델에 맞춰 설정 필요

**공식 지원 에이전트 목록**: Claude Code, Codex, Cursor, OpenCode, WorkBuddy, Hermes Agent, OpenClaw, DeepSeek Harness 등

### 실전 활용 시나리오 (공식 문서 기준)

문서는 API가 없거나 제한적인 서비스에서 특히 유용하다는 점을 강조하며 다음 활용 예시를 제시합니다.

| 영역 | 활용 예시 |
|---|---|
| 소셜 미디어 | X, LinkedIn, Threads, Reddit, Instagram, Facebook에서 답글/인용/게시물 작성, 데이터 수집 |
| 구직/채용 | LinkedIn, Wellfound, YC 채용 정보 검색 및 AshbyHQ·Greenhouse 같은 ATS에 자동 지원 |
| 부동산/금융/쇼핑 | Redfin, Zillow, Amazon 가격 비교, 모기지 계산 |
| 예약 | 항공편/호텔/레스토랑 예약 자동화 (개인정보 입력부터 결제 전 단계까지) |
| SaaS 백엔드 | HubSpot, Salesforce, Notion, Airtable, Linear, Stripe 등에서 자동 보고서 생성, 대량 데이터 업데이트 |
| 내부 도구 | API가 노출되지 않은 관리자 패널이나 스테이징 환경 자동화 |

이 목록은 [리뷰 영상](/ai/ego-browser-review/)에서 보여준 유튜브 스튜디오 분석, 항공권 검색, 사이트 디버깅 데모와 정확히 같은 맥락 — **API가 없거나 접근이 제한된 서비스를, 로그인된 실제 브라우저 상태 그대로 자동화**하는 용도입니다.

### 제한 사항

- 현재 Mac 전용 설치 파일만 제공
- 에이전트마다 권한 설정 UX가 달라서, 처음 붙일 때 에이전트별 권한 모델을 따로 확인해야 함
- API가 이미 잘 노출된 서비스라면 굳이 브라우저 자동화를 거칠 필요가 없음 — 이 툴의 강점은 **API 미노출 서비스**에 집중되어 있음

### 정리

공식 문서를 종합하면 ego-browser는 "AI 에이전트용 Playwright 대체품"이라기보다는, **로그인 세션이 필요하고 매번 상황이 달라지는 인터랙티브 자동화**를 여러 에이전트가 충돌 없이 수행하도록 만든 전용 런타임에 가깝습니다. 반복 가능한 시나리오를 코드로 고정해 헤드리스로 빠르게 돌리는 용도라면 여전히 Playwright 계열이 적합하고, 로그인 상태를 유지한 채 비정형·병렬 작업을 시켜야 한다면 ego-browser 쪽이 낫다는 것이 문서와 리뷰 양쪽 모두에서 일관되게 나오는 결론입니다.
